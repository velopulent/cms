## REST

Content routes live under `/api/v1/sites/{site_id}`; `GET /api/v1/sites` lists accessible sites. Entry and singleton updates use `PATCH`, and publication uses separate `POST …/publish` and `POST …/unpublish` operations. Binary delivery uses `/api/files/{id}`; signed uploads use `PUT /api/v1/files/upload/{token}`.

`/api/v1/docs` serves interactive documentation and `/api/v1/openapi.json` the installed OpenAPI contract.

## GraphQL

The query root holds `sites` and `site(id:)`; all content reads sit under `site`. Mutations take an explicit `siteId`. Authenticated introspection is the field-level reference. Production mode turns off GraphiQL.

## gRPC

| Service | Operations |
| --- | --- |
| `SiteService` | List and get |
| `CollectionService` | List and get schema |
| `EntryService` | List, get, create, update, delete, publish, unpublish, revisions |
| `SingletonService` | List, get, update |
| `FileService` | List, get, references, streaming upload, trash, restore |

`cms.proto` and server reflection describe every message.

## MCP

Tools cover sites, entries, publication, revisions, singletons, files, and signed upload URLs. Collection and singleton schemas are resources. Call `tools/list`, `resources/list`, and `resources/templates/list` for the installed surface.
