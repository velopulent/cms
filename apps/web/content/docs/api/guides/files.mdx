---
title: Deliver and upload files
description: Serve originals and thumbnails, or create signed one-use upload URLs.
---

## Serve a file

Originals and thumbnails use opaque file IDs:

```text
GET /api/files/{id}
GET /api/files/{id}/thumbnail
```

These delivery routes do not require bearer authentication. Do not treat an opaque file URL as access control for confidential media.

Filenames must be nonempty, contain no control characters, and fit within 255 UTF-8 bytes. Delivery headers use an ASCII fallback plus RFC 5987 UTF-8 filename encoding.

## Upload through REST

Send multipart form data to `/api/v1/sites/{site_id}/files` with `files.write`. Include the `file` field; storage is selected from the site configuration.

## Upload through MCP

Call `create_file_upload` with `site_id`, `filename`, and `content_type`. Send one HTTP `PUT` to the returned URL with raw bytes and the exact `Content-Type`. The signed URL expires and can start one upload attempt. Request a fresh URL after a failed or interrupted attempt; deleting a file does not make its URL reusable.

```bash
curl -X PUT "$UPLOAD_URL" \
  -H "Content-Type: image/webp" \
  --data-binary @cover.webp
```

The response contains the created file record. Store a canonical relative URL such as `/api/files/{id}` in a file field. Keep the ID for metadata, delete, and restore operations. Absolute HTTP(S) URLs are treated as external links.
