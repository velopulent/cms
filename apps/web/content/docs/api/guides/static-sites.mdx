---
title: Connect a static site
description: Fetch published content during a frontend build and trigger rebuilds after editorial changes.
---

## Store the credential

Create a read-only site key and save it in your host's build-time secret store as `VCMS_TOKEN`. Save the server's public URL as `VCMS_URL`.

## Fetch during build

```ts
const response = await fetch(
  `${process.env.VCMS_URL}/api/v1/entries?type=posts&status=published&per_page=100`,
  {
    headers: {
      Authorization: `Bearer ${process.env.VCMS_TOKEN}`,
    },
  },
);

if (!response.ok) {
  throw new Error(`VCMS request failed: ${response.status}`);
}

const { items: posts } = await response.json();
```

Keep this code on the build server. Shipping the bearer token to browser JavaScript exposes it.

## Rebuild after publication

Add the hosting provider's build-hook URL under **Deploy**. Editors can publish several entries, then run the trigger. Configure cooldown and daily quota to prevent accidental build storms.

## Handle missing content

Treat optional fields as optional. A newly required field does not retroactively fill old entries. Decide whether the build skips incomplete content, supplies a fallback, or fails with a specific error.
