---
title: Use gRPC
description: Connect typed service clients to the VCMS gRPC listener.
---

VCMS Server listens on `127.0.0.1:50051` by default. Generate a client from `libs/proto/cms.proto` or the proto file bundled with your source release.

## Services

The schema defines Collection, Entry, Singleton, File, and Site services. Collection and Site services expose discovery only; management remains dashboard-only. Entry operations include publishing, unpublishing, and revisions. File operations include trash and restore.

## Authentication

Attach the bearer credential as gRPC metadata:

```text
authorization: Bearer vcms_site_…
# Personal tokens (vcms_pat_…) are also accepted.
```

Include `site_id` on site-scoped requests. Typed `Struct` fields carry dynamic content; legacy JSON text fields remain during migration. Draft reads require `include_drafts` and `content.preview.read`.

## Inspect with grpcurl

When your environment supports server reflection, list services with:

```bash
grpcurl -plaintext -H "authorization: Bearer $VCMS_TOKEN" \
  127.0.0.1:50051 list
```

Otherwise pass the proto file explicitly. Treat that file as the field-level reference for your installed version.

## Network placement

The default listener accepts local connections only. Change `[server].grpc_address` in `config.toml` or place a compatible proxy in front of it when remote clients need access. Protect remote gRPC traffic with TLS at the service or proxy boundary.

Health and reflection endpoints are unauthenticated. Keep the listener within a controlled network boundary. Content responses currently populate both legacy JSON and typed fields; large responses may require a higher client decoding limit than the generated client's 4 MiB default.
