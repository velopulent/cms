---
title: Authentication
description: Choose, send, scope, rotate, and revoke VCMS API credentials.
---

Send API credentials as a bearer token:

```http
Authorization: Bearer vcms_site_…
```

## Site keys

Site keys begin with `vcms_site_`. They identify one site and work with public REST, GraphQL, gRPC, and MCP according to their scopes. Choose read access for delivery applications. Use write access only for trusted automation that changes content or site resources.

## Personal tokens

Personal tokens begin with `vcms_pat_`. They carry a user's identity plus selected scopes. Use them for user-owned tools, CLI clients, and MCP connections that need the same site access as that user.

## Dashboard sessions

The dashboard uses a cookie session and CSRF token. Do not automate `/api/dashboard` with a site key. Public integrations should use protocol endpoints and bearer credentials.

## Credential handling

- Store tokens in your deployment platform's secret store.
- Give each integration its own token and descriptive name.
- Select the smallest scope set.
- Copy a new raw token once, then close the dialog.
- Revoke exposed or unused tokens and replace them at the consumer.

<Callout type="warn">
URLs, screenshots, logs, and source code are unsafe places for bearer tokens. Never pass a token in a query string.
</Callout>
